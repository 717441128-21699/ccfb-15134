# 有声书打包工具

把几十个分章 MP3 拖进网页,自动拼接成整本有声书,一次导出两种成品:

- **M4B**:MP3 帧流直接装进 MP4 容器(不转码、零音质损失),章节双写 ——
  Nero `chpl`(udta)+ QuickTime 文本章节轨(音频轨 `tref/chap` 引用),
  元数据走 iTunes 风格 `ilst`(标题/演播/专辑/年份/类型/备注/封面)。
- **MP3**(给老播放器):整本单文件,ID3v2.4 标签写入 `CHAP`/`CTOC` 章节帧、
  文本帧与 `APIC` 封面。

纯 TypeScript 实现,**不依赖任何音频封装库**(MP3 帧索引、ID3、MP4 mux 全是手写),
运行时零依赖,构建只需 TypeScript 编译器。

## 使用

```bash
npm install
npm run build
npm run serve     # http://localhost:8080/
```

四个页面:

1. **书目**:书名、演播、专辑、年份、类型、备注、封面(PNG/JPEG)。
2. **章节编辑**:拖入分章 MP3(按文件名自然排序),可改标题、调顺序、删除;
   每章显示时长与起始时间。
3. **导出**:导出 M4B / MP3,显示封装耗时与文件大小。
4. **校验**:把成品拖进来重新解析,列出章节表与元数据,和当前工程逐项比对(容差 ±10ms)。

## 精度与性能

- 章节点 = 前序各段**采样数**累加 ÷ 采样率,逐帧解析帧头得到,不解码音频;
  换算到毫秒误差 ≤0.5ms,远优于 10ms 要求。
- M4B 的 QuickTime 章节轨与音频轨共用采样率时基,章节点落在精确采样边界上;
  Nero chpl 用 BigInt 精确换算到 100ns。
- 拼接只做字节搬运(Blob 切片零拷贝),帧表用 `Uint32Array`;
  30 小时(约 413 万帧、1.7GB)封装实测秒级完成(见 `npm test` 输出)。

## 测试

```bash
npm run gen-samples   # 合成三本测试书:
                      #   雪夜行 12 章 44.1kHz 立体声(可播放)
                      #   灯下短篇集 63 章 22.05kHz 单声道(MPEG-2 路径,可播放)
                      #   长河录 40 章 × 45 分钟 = 30 小时(合成帧,性能测试用)
npm test              # 端到端:导出→自解析→ffprobe 第三方校验→30 小时性能测试
```

`gen-samples` 需要系统里有 ffmpeg;`npm test` 里的第三方校验需要 ffprobe,
没有会自动跳过(不影响自解析校验)。可播放的两本书用 ffmpeg 合成正弦波,
各章音调不同,便于听辨章节边界是否准确。

## 限制与说明

- 整本书的分章文件编码参数必须一致(采样率、声道、Layer),否则 M4B 的
  `stsd/stts` 无法描述,导出页会明确报错;MP3 导出同样拒绝,避免产出错位章节。
- 源文件的 ID3v2 / ID3v1 标签在拼接时自动剥离;帧流中的垃圾字节会重新同步跳过。
- Nero `chpl` 与 `CTOC` 的章节计数是 8 位,超过 255 章时只列前 255 个
  (QuickTime 章节轨与 CHAP 帧不受限,导出页会提示)。
- 章节点按帧边界对齐;MP3 编码器固有的启始延迟(encoder delay)属于源文件本身,
  不在本工具处理范围内。
- 音频时长超过约 27 小时(44.1kHz 下采样数超 2³²)时,`mdhd` 自动切换为
  version 1(64 位时长),主流播放器均支持。
